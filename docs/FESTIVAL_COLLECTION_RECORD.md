# 학술제 작성용 KBO 기록 수집·검증 기록

> 작성일: 2026-08-11  
> 이 문서는 학술제 본문에서 **자료 수집과 전처리 방법**, **자료의 신뢰성 확인**, **연구의 한계**를 쓸 때 사용할 근거 기록이다. 아직 만들지 않은 예측 모델의 성능이나 결론은 넣지 않는다.

## 1. 이 기록을 남기는 이유

이번 연구는 KBO 선수의 경기별 기록을 바탕으로 선수의 컨디션과 경기 결과를 분석하려는 연구다. 분석 결과가 믿을 만하려면 모델을 만들기 전에 다음 질문에 답할 수 있어야 한다.

1. 어떤 경기와 선수 기록을 어디에서 가져왔는가?
2. 한 줄의 데이터는 정확히 무엇을 뜻하는가?
3. 중복·빈칸·범위 밖 경기를 어떻게 처리했는가?
4. 저장한 값이 원본 기록과 실제로 맞는지 어떻게 확인했는가?

따라서 이 문서는 "많은 데이터를 모았다"는 설명이 아니라, 나중에 학술제 보고서에서 수집 과정과 판단 근거를 재현할 수 있게 남기는 작업 기록이다.

## 2. 연구에서 수집한 자료의 범위

### 2.1 대상 기간

| 구분 | 기간 | 사용 목적 | 현재 수집 범위 |
|---|---|---|---|
| 최근 확인 자료 | 2026년 5월 | 경기·타석·투구 연결 규칙을 확인 | 일정, 선수별 경기, 1군 등록, 경기 전체 투구 연결 |
| 과거 시즌 자료 | 2021~2024년 정규시즌 | 여러 시즌의 선수별 경기 기록 확보 | 일정, 점수판, 박스스코어, 선수별 경기 기록, Naver 1회 중계 원본 |

과거 시즌에는 시즌마다 정규시즌 720경기, 총 2,880경기를 분석 대상에 넣었다. 2022~2024년 올스타전 3경기는 일정 원본에는 남기되 정규시즌 분석 표에서는 제외했다. KBO 검토 링크가 없는 일정 351행은 취소·미개최·화면 구조 차이 중 무엇인지 확정하지 않았으므로, 분석 대상에 넣지 않고 별도 목록으로 보관했다.

### 2.2 자료 출처

| 자료 | 출처 | 수집한 이유 | 원본 보관 형식 |
|---|---|---|---|
| 시즌별 일정 | KBO 공식 일정 | 대상 경기의 날짜·팀·경기 번호를 정하는 기준 | JSON |
| 경기 점수판 | KBO 공식 경기 화면 | 경기의 기본 결과와 공식 경기 응답 확인 | JSON |
| 박스스코어 | KBO 공식 경기 화면 | 이닝별 기록과 선수 기록을 원본으로 보관 | JSON |
| 선수별 경기 기록 | Naver Sports 경기 중계의 선수 명단 | 선수 번호와 타석·타수·안타·홈런·볼넷·삼진을 연결 | JSON에서 CSV로 정리 |
| 선수 일별 기록 | KBO 공식 선수 기록 화면 | 임의로 고른 선수 한 명의 경기 기록을 직접 대조 | HTML |

KBO 원본은 공식 대조 근거로, Naver 선수 명단은 선수 번호와 기본 타격 기록을 얻는 자료로 사용했다. 이름만 같다는 이유로 서로 다른 원본의 선수를 임의로 연결하지 않았다.

## 3. 수집 과정

### 3.1 경기 목록 만들기

먼저 KBO 일정 원본에서 날짜, 원정 팀, 홈 팀, 경기장, 경기 번호를 읽어 `game_schedule.csv`를 만들었다. 이 표의 한 줄은 KBO 일정의 경기 한 건 또는 경기 번호가 없는 일정 한 건이다.

일정에서 `나눔`과 `드림`이 맞붙은 세 경기는 올스타전으로 확인했다. 이 경기는 정규시즌 승률·컨디션 분석과 성격이 다르므로 `EXCLUDED_ALL_STAR` 상태로 분리했다. 경기 번호가 없는 351행은 원인을 확인하기 전까지 `NO_REVIEW_ID` 상태로 남겼다.

### 3.2 경기 원본 저장하기

정규시즌 경기 한 건마다 다음 세 원본이 모두 있을 때만 "완전한 경기 원본"으로 셌다.

| 파일 | 내용 | 확인 기준 |
|---|---|---|
| `kbo_scoreboard.json` | KBO 점수판 응답 | 파일이 있고 JSON으로 읽힘 |
| `kbo_boxscore.json` | KBO 박스스코어 응답 | 파일이 있고 JSON으로 읽힘 |
| `naver_relay_inning_1.json` | Naver 1회 중계와 선수 명단 응답 | 파일이 있고 JSON으로 읽힘 |

수집 중 중간에 프로그램이 멈추거나 다시 실행될 수 있으므로, 폴더만 존재한다고 완료로 처리하지 않았다. 세 파일이 모두 존재하는지를 다시 검사했다. 이미 세 파일이 있는 경기는 다시 요청하지 않게 하여, 요청 간격을 바꾸어 재실행해도 원본을 중복 저장하지 않도록 했다.

### 3.3 선수별 경기 표 만들기

`player_game_boxscore.csv`는 선수 한 명의 경기 한 번을 한 줄로 만든 표다. 같은 선수가 같은 경기에서 두 줄로 들어가지 않게 `game_id + player_id`를 기준으로 확인했다.

| 열 이름 | 뜻 | 예시 값 | 주의할 점 |
|---|---|---|---|
| `game_id` | KBO 경기 번호 | `20210627LTOB0` | 경기 날짜나 팀 이름만으로 대신하지 않음 |
| `game_date` | 경기 날짜 | `2021-06-27` | YYYY-MM-DD 형식 |
| `team` | 해당 선수의 팀 | 롯데 | 경기 당시 팀 |
| `home_away` | 홈·원정 | `AWAY` | 경기 일정에서 정함 |
| `player_id` | Naver 선수 번호 | `50506` | 이름만으로 선수를 구분하지 않음 |
| `player_name` | 선수 이름 | 마차도 | 원본 표기 유지 |
| `PA` | 타석 수 | `4` | 원본이 비어 있으면 0으로 바꾸지 않음 |
| `AB` | 타수 | `3` | 원본 값 |
| `H` | 안타 수 | `1` | 원본 값 |
| `HR` | 홈런 수 | `0` | 원본 값 |
| `BB` | 볼넷 수 | `1` | 원본 값 |
| `SO` | 삼진 수 | `1` | 원본 값 |
| `quality_flag` | 확인 상태 | `CHECK` | 전체 행이 KBO 선수 일별 기록과 대조된 것은 아님 |

| 항목 | 저장 표 | KBO 공식 일별 기록 | 결과 |
|---|---:|---:|---|
| 타석 | 4 | 4 | 일치 |
| 타수 | 3 | 3 | 일치 |
| 안타 | 1 | 1 | 일치 |
| 홈런 | 0 | 0 | 일치 |
| 볼넷 | 1 | 1 | 일치 |

KBO 선수 일별 기록 화면은 처음 열면 현재 시즌을 보여 주었다. 과거 시즌을 검사하려면 화면의 시즌 선택값을 해당 연도로 바꾼 뒤 기록을 찾아야 했다. 그래서 검사 프로그램이 선수 번호와 경기 날짜에서 연도를 읽어, 해당 시즌을 선택한 뒤 비교하도록 수정했다.

## 5. 수집 중 발견한 문제와 처리

### 5.1 빈 타석 값을 0으로 바꾸지 않음

2021년 일부 Naver 선수 명단에는 타석 값이 실제로 비어 있었다. 예를 들어 2021년 6월 4일 삼성 대 키움 경기의 김혜성은 타수 5, 안타 1, 삼진 1이 있으나 타석 원본값은 비어 있었다.

빈칸을 0으로 바꾸면 "타석이 없었다"는 잘못된 뜻이 된다. 따라서 9,226행의 빈 타석 값은 빈칸으로 유지하고 `CHECK` 상태로 표시했다.

타석은 단순히 타수와 볼넷을 더해서 확정할 수도 없다. 몸에 맞는 공, 희생번트, 희생플라이, 타격·수비 방해로 출루한 경우가 함께 들어갈 수 있기 때문이다. 이런 항목을 모두 원본에서 확인하기 전에는 계산값으로 타석을 채우지 않는다.

### 5.2 수집 중인 폴더와 완료된 폴더 구분

수집기는 경기 폴더를 먼저 만들고 세 원본 파일을 차례로 저장한다. 따라서 프로그램이 아직 실행 중일 때는 폴더는 있지만 파일이 한두 개만 있는 상황이 생긴다. 이때 폴더 수만 세면 진행 중인 경기를 실패로 잘못 판단할 수 있다.

해결 방법은 세 파일이 모두 있는지를 검사하는 것이었다. 처음에는 수집 오류처럼 보였던 세 건도 일정 원본을 다시 읽어 보니 올스타전이었으며, 실제 정규시즌 수집 오류로 처리하지 않았다.

### 5.3 기존 자료를 덮어쓰지 않음

2026년 5월에 이미 확인한 자료와 2021~2024년 백필 자료를 한 폴더에 저장하면, 뒤에 실행한 범위의 CSV가 앞의 결과를 덮어쓸 수 있다. 그래서 결과 폴더를 다음처럼 분리했다.

| 자료 | 저장 위치 |
|---|---|
| 2026년 5월 확인 자료 | `data/research_40_110/` |
| 2021~2024년 정규시즌 자료 | `data/research_80_backfill/` |

수집 프로그램에는 결과 폴더를 따로 지정하는 선택지를 추가했다. 이 방식으로 서로 다른 기간의 원본·표·로그를 독립적으로 보관한다.

## 6. 현재 자료로 할 수 있는 것과 아직 할 수 없는 것

| 구분 | 가능한 것 | 아직 하면 안 되는 것 |
|---|---|---|
| 선수별 경기 기록 | 경기별 타석·타수·안타 등 기본 기록을 이용한 분석 | 빈 타석 값을 0 또는 계산값으로 확정 |
| 시즌별 경기 수 | 정규시즌 2,880경기의 수집 여부와 중복 확인 | 검토 링크 없는 351행을 모두 취소 경기라고 단정 |
| 과거 시즌 중계 | 선수 명단과 1회 중계 원본 확인 | 1회 자료만으로 경기 전체 투구·타석 순서를 분석 |
| KBO 공식 대조 | 표본 선수·경기의 실제 값 비교 | 한 표본 일치만으로 전체 행이 모두 공식 대조되었다고 주장 |

## 7. 학술제 본문에 쓸 때의 권장 구성

작년 학술제 자료의 구성 방식은 참고하되, 이번 연구에는 아래 내용을 사용한다.

1. **연구 동기와 목적**: 야구 경기 기록은 선수 개인의 최근 경기 상태와 경기 상황을 함께 볼 수 있는 자료이며, 이를 바탕으로 선수 컨디션과 경기 결과를 분석하려는 목적을 쓴다.
2. **자료 수집**: KBO 공식 일정·점수판·박스스코어와 Naver 경기 중계에서 어떤 정보를 받았는지, 대상 기간이 2021~2024 정규시즌 2,880경기임을 쓴다.
3. **자료 정리**: 선수 한 명의 한 경기를 한 줄로 만드는 방법과 `game_id + player_id` 중복 검사를 설명한다.
4. **자료 신뢰성 확인**: 세 원본 파일 확인, 중복 0행, 표본 1건의 6개 항목 공식 대조를 표로 제시한다.
5. **한계**: 빈 타석 9,226행, 검토 링크 없는 일정 351행, 과거 시즌의 경기 전체 투구 기록 미수집을 명확히 쓴다.
6. **별첨**: 파일별 열 이름·순서표, 수집 명령, 표본 대조표, 수집 오류·처리 기록을 붙인다.

보고서에는 "모든 기록이 완벽하다"라고 쓰지 않는다. 확인한 범위, 확인하지 못한 범위, 이를 어떻게 표시했는지를 함께 써야 자료를 다룬 과정이 설득력을 가진다.
