# 80번 과거 시즌 수집: 확인한 문제와 처리 기록

이 문서는 2026-08-11에 2021~2024년 KBO 과거 시즌 자료를 다시 모으면서 실제 원본과 수집 결과를 확인해 남긴 기록이다. 확인하지 않은 값을 정상값으로 바꾸지 않으며, **해결됨**과 **추가 확인 필요**를 분리한다.

## 수집 범위와 현재 상태

- KBO 일정 응답에서 2021년 853경기, 2022년 770경기, 2023년 814경기, 2024년 797경기, 총 3,234개의 완료 경기 행을 받았다.
- 각 경기에는 KBO 점수판 원본, KBO 박스스코어 원본, 네이버 1회 중계 원본을 따로 저장한다.
- 과거 시즌 수집 중에는 이미 완료한 2026년 5월 자료를 덮어쓰지 않도록 별도 폴더를 사용한다.

## 해결하거나 방지한 문제

### 1. 과거 시즌 수집이 기존 CSV를 덮어쓸 수 있었음

처음 수집기는 기본 저장 위치 하나만 사용했다. 다른 시즌을 같은 위치에서 실행하면 일정·선수×경기 CSV가 새 시즌 범위로 다시 만들어져, 먼저 검증한 2026년 5월 결과가 사라질 수 있었다.

- 처리: `--data-root` 선택지를 추가했다.
- 2026년 5월 자료: `data/research-40-110/`
- 2021~2024년 백필 자료: `data/research-80-backfill/`
- 결과: 두 범위의 원본과 CSV가 섞이지 않는다.

### 2. 수집 중인 경기 폴더를 실패로 잘못 셀 수 있었음

수집기는 경기 폴더를 먼저 만들고 KBO 점수판, KBO 박스스코어, 네이버 중계 파일을 차례로 저장한다. 따라서 막 시작한 경기 폴더에는 한두 파일만 있을 수 있다.

- 잘못된 판단: 폴더가 있는데 파일 하나가 없으면 수집 실패라고 판단.
- 현재 규칙: 세 파일이 모두 있을 때만 `완료된 경기 원본`으로 센다.
- 결과: 수집 중인 마지막 경기와 실제 오류를 구분할 수 있다.

### 3. 실시간 출력 로그가 비어 보였음

장시간 실행한 Python 프로그램의 표준 출력은 종료 시점까지 파일에 바로 기록되지 않을 수 있다. 그래서 실행 중에는 출력 로그가 비어 있었지만, 원본 경기 폴더 수는 계속 증가했다.

- 처리: 표준 출력만 보지 않고 Python 프로세스, 오류 로그, 세 원본 파일이 모두 있는 경기 폴더 수를 함께 확인한다.
- 결과: 실제 진행률은 완성된 경기 폴더 수 ÷ 공식 일정 3,234경기로 보고한다.

### 4. 요청 간격을 조정하면서 이미 받은 원본을 다시 받을 위험

처음 과거 시즌 수집은 요청 사이를 1.2초로 두었다. 이후 1.0초로 줄일 때 프로세스를 다시 시작해야 했다.

- 처리: 이미 존재하는 원본 파일은 다시 요청하지 않는 방식으로 재시작했다.
- 결과: 앞서 받은 경기 원본을 지우거나 중복 저장하지 않고 속도만 조정했다.

### 5. 한글이 깨져 보이는 화면과 실제 원본 훼손을 구분해야 함

터미널 또는 복사한 텍스트에서는 KBO 표 안의 한글이 깨져 보일 수 있다. KBO 박스스코어는 표 JSON을 문자열 안에 다시 넣어 보내므로, 복사 과정에서 따옴표와 문자 인코딩이 더 쉽게 깨진다.

- 처리: 붙여넣은 화면이 아니라 저장한 UTF-8 JSON을 직접 읽고, KBO 응답 코드와 JSON 파싱 성공 여부를 함께 확인한다.
- 결과: 화면 표시 문제만으로 원본이 망가졌다고 판단하지 않는다.

## 실제 값에서 발견한 중요한 문제

### 6. 비어 있는 PA를 0으로 쓰면 잘못된 기록이 됨

네이버 선수 명단에는 선수 번호, 타수, 안타, 홈런, 볼넷, 삼진 등이 들어 있다. 하지만 2021년 일부 경기에서는 `PA`가 실제로 비어 있었다.

실제 예: 2021-06-04 삼성 대 키움 경기의 김혜성은 타수 5, 안타 1, 삼진 1이지만 PA 원본값은 비어 있었다.

- 이전 처리의 문제: 비어 있는 수치를 0으로 바꾸면 `타석이 없었다`는 거짓 기록이 된다.
- 처리: 비어 있는 값은 빈칸으로 보존한다. 해당 선수×경기 행은 `CHECK` 상태로 남긴다.
- 금지: 원본에 없는 PA를 0으로 채우지 않는다.

### 7. PA는 타수와 볼넷만으로 정확히 계산되지 않음

정확한 타석은 보통 다음을 모두 포함한다.

`PA = AB + BB + HBP + SH + SF + 타격·수비 방해로 1루가 주어진 경우`

안타·삼진·일반 아웃·실책 출루 등은 이미 AB에 들어간다. 고의사구는 BB에 포함된다.

- 현재 네이버 원본: AB, BB, HBP는 확인되지만 일부 시즌에서 SH·SF가 별도 수치로 바로 제공되지 않는다.
- 현재 KBO 박스스코어: 선수별 이닝 결과 표(`arrHitter`의 `table2`)가 있어 타석 수를 다시 만들 가능성은 있다.
- 아직 해야 할 일: KBO 이닝 결과 표와 전체 중계 사건을 비교해 희생타·대타 교체·이닝 종료 예외까지 맞는지 검증한 뒤에만 PA를 계산값으로 채운다.
- 현재 결론: 직접 PA가 없으면 빈칸 + CHECK가 맞다.

### 8. KBO 박스스코어는 바로 쓰기 어려운 중첩 표 구조임

KBO 박스스코어 원본에는 `arrHitter`와 `arrPitcher`가 있다. 각 팀의 `arrHitter`에는 다음 표가 문자열 JSON으로 들어 있다.

- `table1`: 타순·수비 위치·선수 이름
- `table2`: 이닝별 타석 결과
- `table3`: 타수·득점·안타·타점·타율 등 요약
- `tfoot`: 팀 합계

- 주의: `tfoot`은 팀 합계이므로 선수 행으로 넣으면 안 된다.
- 주의: 현재 확인한 KBO 표에서 선수 번호와 분석용 열을 바로 안정적으로 읽는 방식은 아직 확정하지 않았다.
- 처리: 선수 번호와 기본 타격 수치는 네이버 중계의 선수 명단에서 가져오고, KBO 원본은 공식 대조 근거로 보관한다.

### 9. 같은 이름만으로 선수 연결을 확정하면 안 됨

KBO 표에는 선수 이름이 있고, 네이버 중계에는 선수 번호(`pcode`)와 이름이 함께 있다. 이름만 같다고 같은 선수라고 단정하면 동명이인 또는 표기 차이 문제를 놓칠 수 있다.

- 처리: 최종 선수×경기 표는 네이버 선수 번호를 기본 키로 사용한다.
- 추가 확인: KBO 공식 일별 기록과의 직접 대조를 더 많은 경기로 넓혀야 한다.
- 현재 증거: 2026-05-01 허인서 한 건에서 PA·AB·H·HR·BB·SO 여섯 값이 모두 일치했다. 이것은 전체 경기에 대한 증명은 아니다.

### 10. 1군 등록 원본에는 확인한 선수 번호가 없음

KBO 1군 등록 원본은 날짜·팀·선수 이름·포지션은 제공하지만, 현재 확인한 화면에는 분석에 바로 쓸 선수 번호가 없다.

- 처리: `roster_daily.csv`의 `player_id`를 빈칸으로 보존하고 `CHECK`로 표시한다.
- 금지: 이름만 보고 선수 번호를 임의로 채우지 않는다.

### 11. 일정의 완료 행과 연구에서 쓸 정규시즌 범위는 별도 확인이 필요함

현재 일정 수집은 KBO 요청 조건에 따라 완료 경기 3,234행을 받았다. 하지만 CSV에는 경기 시리즈 구분을 별도 열로 보관하지 않는다.

- 주의: 이 수를 곧바로 `정규시즌 경기 수`라고 단정하지 않는다.
- 해야 할 일: 연구 범위가 정규시즌만인지, 포스트시즌·시범경기를 포함하는지 먼저 정하고, 시리즈 구분을 확인할 수 있는 원본 필드를 보존한다.

### 12. 현재 과거 시즌 단계는 모든 투구를 아직 받지 않음

80번 백필에서는 먼저 경기 수를 맞추기 위해 경기별 점수판·박스스코어·네이버 1회 중계를 받고 있다. 전체 이닝의 투구 원본은 아직 별도 단계다.

- 가능한 것: 경기·선수별 기본 기록, 경기 수 대조, 선수 명단 확인.
- 아직 불가능한 것: 과거 시즌 전체의 정확한 타석 순서, 모든 공의 구종·구속·위치 분석.
- 금지: 1회 중계만으로 경기 전체 타석·투구가 모두 있다고 주장하지 않는다.

## 현재 사용 원칙

1. 원본이 비어 있으면 0이 아니라 빈칸 또는 CHECK로 남긴다.
2. 팀 합계와 선수 행을 섞지 않는다.
3. 수집 중인 폴더와 완성된 원본을 구분한다.
4. KBO 원본, 네이버 원본, 가공 CSV의 출처를 한 행에서 추적할 수 있게 보관한다.
5. 예시 한 건의 일치는 전체 시즌의 일치 증거가 아니므로, 검증 범위를 따로 기록한다.
6. 과거 시즌 수집이 끝난 뒤에만 시즌·팀별 공식 경기 수와 저장 경기 수를 다시 대조한다.

## 완료 후 확정한 결과 (2026-08-11)

### 13. KBO 응답 코드가 200인 세 건은 수집 오류가 아니라 올스타전이었다

재시도 뒤에도 `20220716WEEA0`, `20230715EAWE0`, `20240706WEEA0` 세 경기는 KBO 점수판 응답의 코드가 200으로 남았다. 일정 원본을 다시 확인한 결과, 세 경기는 각각 2022·2023·2024 올스타전의 `나눔` 대 `드림` 경기였다.

- 처리: 실패로 재시도하지 않고 `EXCLUDED_ALL_STAR`로 따로 표시했다.
- 정규시즌 연구 범위: 시즌마다 720경기, 2021~2024년 합계 2,880경기.
- 보관: 세 경기의 일부 원본 폴더는 삭제하지 않았지만, 분석용 경기표와 선수별 경기표에는 넣지 않았다.
- 금지: 코드 200만 보고 "수집 실패"라고 단정하거나 올스타전을 정규시즌 표본에 섞지 않는다.

### 14. 수집과 검증 결과

| 항목 | 결과 | 확인 방법 |
|---|---:|---|
| KBO 일정 행 | 3,234행 | `game_schedule.csv` |

표본 대조도 했다. 2021-06-27 롯데 원정 경기의 마차도(선수 번호 50506)는 표의 PA 4, AB 3, 안타 1, 홈런 0, 볼넷 1, 삼진 1이 KBO 선수 일별 기록과 6개 모두 일치했다. 과거 시즌을 검사할 때는 KBO 페이지가 처음에는 현재 시즌을 보여 주므로, 검사 프로그램이 해당 연도로 바꾼 뒤 비교하도록 고쳤다.

### 15. 아직 분석 전에 확인해야 하는 범위

- 9,226행은 원본 선수 명단의 PA가 비어 있다. 이 값은 0으로 바꾸지 않았고 빈칸과 `CHECK` 상태로 남겼다.
- 이번 과거 시즌 수집은 경기당 Naver 1회 중계 원본까지다. 경기 전체 투구·타석 순서를 모두 복원한 자료가 아니므로, 과거 시즌 전체 투구 분석에는 바로 쓰지 않는다.
- `NO_REVIEW_ID` 351행은 취소·미개최·화면 구조 차이 등을 아직 분류하지 않은 일정 행이다. 이 행이 모두 취소 경기라는 뜻은 아니다.

## 다음 확인 순서

1. 모든 과거 경기의 세 원본 파일 수집 완료 여부를 검사한다.
2. KBO 완료 경기 목록과 저장 경기 목록의 차이, 중복, 시리즈 범위를 확인한다.
3. KBO 이닝 결과 표로 PA를 재구성할 수 있는지 표본 경기부터 검증한다.
4. 직접 PA가 없는 행은 빈칸과 CHECK를 유지한다.
5. 검증 결과와 남은 차이를 Notion 실제 수집 결과 페이지와 80번 작업 메모에 반영한다.
