# 프로젝트 설계

## 목표

타자의 최근 경기 상태를 벡터로 표현하고 그 벡터의 방향·속도·변화점을
이용해 다음 컨디션 사이클을 예측한다. 인공신경망을 전제로 하지 않으며,
해석 가능한 시계열·상태공간 방법을 우선한다.

## 전체 파이프라인

```text
날짜별 일정 탐색
  → 실제 경기 ID 발견
  → Naver 중계·PTS와 KBO 공식 데이터 수집
  → 원본 JSON/HTML gzip 보존
  → 경기·타석·투구·선수 일별 데이터 정규화
  → 무결성 검사와 오류 경기 격리
  → 타자×일자 특징 벡터 생성
  → 표준화·PCA 또는 설명 가능한 특징 선택
  → 상태공간/Kalman/HMM/변화점 모델
  → 다음 상태와 Rising/Peak/Falling/Slump 사이클 예측
```

## 권장 타자 상태 벡터

일자 `t`의 타자 상태를 다음과 같이 구성한다.

```text
x_t = [
  PA, AB, H, 2B, 3B, HR, BB, HBP, SO,
  AVG, OBP, SLG, ISO, BB%, K%,
  최근 타구/투구 위치 적합도,
  평균 상대 투수 난이도,
  출전 간격, 연속 출장일,
  1군 등록 상태,
  구장·홈/원정·경기 상황
]
```

원시 개수는 최근 5·10·20타석 또는 3·7·14일 롤링 비율로 바꾸고,
리그·시즌 기준 Z-score를 함께 사용한다.

변화 벡터는 다음처럼 분리한다.

```text
속도: Δx_t = x_t - x_(t-1)
가속도: Δ²x_t = Δx_t - Δx_(t-1)
기준 상태 거리: ||x_t - μ_player||
방향 유사도: cosine(Δx_t, Δx_(t-1))
```

## 비신경망 모델 후보

1. Kalman filter 또는 동적 선형 모형
   - 연속적인 잠재 컨디션과 관측 잡음을 분리한다.
2. Gaussian HMM
   - Rising, Peak, Falling, Slump 같은 이산 상태를 추정한다.
3. 변화점 탐지
   - 부상, 2군 이동, 타격폼 변화처럼 상태 전환이 갑작스러운 구간을 찾는다.
4. VAR/동적 회귀
   - 투수 난이도, 휴식, 구장과 컨디션 변화의 시차 관계를 모델링한다.
5. 생존분석
   - 현재 사이클이 언제 종료될지 지속시간을 예측한다.

## 데이터 설계 원칙

- 경기 ID는 일정 응답에서 발견한 값만 사용한다.
- 시간 순서는 `relay_no`, `seqno`, 원본 `pitch_num`으로 유지한다.
- 투구 키는 `(game_id, pitch_id)`다. Naver `pitch_id`는 동시 경기에서
  중복될 수 있다.
- 이벤트 relay와 실제 타석 relay를 구분한다.
- 오류 데이터를 삭제하지 않고 원본과 함께 `quarantined`로 남긴다.
- 학습/검증 분할은 반드시 시간 순서를 지킨다.
